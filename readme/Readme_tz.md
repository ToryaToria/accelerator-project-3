# Техническое задание

## Общие технические требования

- Адаптивность сетки: отображено на макете. Контейнер фиксированной ширины.
- Вёрстка не должна ломаться при изменении масштаба страницы.
- Используемая методология: БЭМ.
- Используемые фреймворки: нет.
- Используемый препроцессор: Sass (SCSS-синтаксис).
- Используемый инструмент автоматизации: поставляется в самом начале работы. Модификация сборки запрещена.
- Кроссбраузерность: Chrome, Firefox.
- Шрифт:Manrope. Скачать шрифт по ссылке `https://up.htmlacademy.ru/assets/intensives/production-frontender/20/Manrope.woff2.zip` или подобрать самостоятельно.
- JavaScript: необходимо реализовать компоненты с слайдерами, бургерное меню, формы.
- Элементы помечены как контентная область в макете — стилизуются по каскаду.
- Добавлять атрибут class для контентных элементов, помеченных в макете красным, запрещено.
- Любая анимация не должна длиться более 300 ms.

**💡 При разногласиях стайлгайда и макета, макет считать приоритетным.**

## Брейкопойнты:

- мобильная версия — от 320px;
- планшетная версия — от 768px;
- десктопная версия — от 1440px и выше.

## Общее

- Фоны, которые упираются в края макета, должны тянуться на всю страницу.
- Для реализации слайдеров используется библиотека `swiper.js`.

### Шапка

- **Логотип:** никуда не ссылается.

**Бургерное меню:**

- Работает одинаково на любом разрешении экрана.
- При открытии бургерного меню весь экран затемняется.
- Закрытие может происходить при взаимодействии с любой частью экрана, кроме навигации.
- Кнопка «Меню» имеет два состояния: покой и активное.
- **Покой**: взаимодействие с элементом происходит со всей площадью, а не только «тремя полосками».
- **Активное**: ширина становится по ширине контента навигации.
- Кнопка интерактивная и должна иметь все визуальные состояния по сталгайду и критериям.
- Навигация имеет подкатегории.
- Все подкатегории при первом открытии бургерного меню скрыты.
- Одновременно могут быть раскрыты все подкатегории для просмотра всех пунктов навигации.
- Название подкатегории, например «Программы», является интерактивным элементом, а значит может открываться с помощью клавиатуры.
- Все изменения состояний происходят плавно.

### Hero (Promo)

- Изображение занимает весь экран.
- Высота блока - по макету.

- **Блок с текстом:**
- Всегда находится снизу на одинаковом расстоянии.
- Блок должен быть готов к двойному переполнению текстами.
- Блок может съезжать вниз при добавлении текста из DevTools, но должен нормально работать при изменении текста в исходном HTML-файле.

**Слайдер:**

- Зациклен (прокручивается бесконечно).
- Высота рассчитывается автоматически.
- На десктопной ширине отключена возможность перетаскивание слайдов мышкой (allowTouchMove).
- Буллеты являются интерактивными для переключения слайдов.

### О проекте

- Элемент «Подробнее о проекте» открывает модальное окно «Напишите нам».

**Модальное окно «Напишите нам»**:

- Контент полей формы должен проходить валидацию.
- Клик вне модального окна закрывает его.
- Инпуты не имеют подсказок к заполнению (placeholder).
- Первая опция в поле «Выберите город» является пустой. value для данной опции должна быть пустой.
- Поле с телефоном должно иметь маску, начинающуюся с +7
- Чекбокс «Я согласен на обработку моих персональных данных» является обязательным для отправления формы. По умолчанию галочка не проставлена.
- Взаимодействие с кнопкой «Отправить» происходит со всей площадью, а не только с иконкой. Кнопка отправляет данные на сервер, а после закрывает модальное окно.
- Отправка формы возможна только после заполнения всех полей. Отправка формы методом Post.
- Текст сообщения ошибки выводите стандартными браузерными возможностями. Учтите состояния ошибки в стайлгайде.

### Программы

**Слайдер:**

- Не имеет автозапуска.
- Не зациклен.
- Мобильная версия: показывается 1 слайд.
- Планшетная версия: показывается 2 слайда.
- Десктопная версия: показывается 3 слайда. Отключена возможность перетаскивание слайдов мышкой (allowTouchMove).
- Элемент с иконкой стрелки переводит на другую страницу.
- Элементы со стрелками, начиная с планшета, «показать предыдущий слайд» и «показать следующий слайд» перелистывают по одной странице.
- Элемент «Все программы» переводит на другую страницу.
- Пагинация реализована в виде скролл-бара:
  - При переключении страниц меняется положение полосы заливки, на последней странице полоса должна быть в крайнем правом положении
  - Ширина ползунка зависит от количества слайдов в слайдере так, чтобы при переходе между страницами происходил полный переход от крайнего левого положения к крайнему правому. скроллбар должен быть перетаскиваемым
    _(см. пример в `https://swiperjs.com/demos#scrollbar`)_

### Как поехать

- Количество пунктов в блоке «Чтобы получить грант на обучение, вам нужно…» может быть изменено.
- Изображение может быть любого размера как в большую, так и меньшую сторону.
- Изображение может быть изменено из административной части сайта.

### Новости и материалы

**Навигация:** - Элементы навигации — табы.

- Мобильная версия: имеет прокрутку для пунктов навигации, которые ушли за экран.
- Каждый пункт навигации интерактивный. Реализация переключения и смены контента не требуется.

**Слайдер:**

- Не имеет автозапуска.
- Не зациклен.
- На одной странице показывается несколько слайдов.
- Первый слайд на каждой странице всегда большой на десктопе.
- Элементы со стрелками «показать предыдущий» и «показать следующий» и пагинация перелистывают по одному элементу на всех разрешениях.
- Кнопки пагинации позволяют перейти к произвольному слайду.

**Поведение кнопок пагинации:**

_Начальное состояние:_

- Если всего 4 слайда или меньше, отображаются кнопки для всех слайдов.
- Если больше 4 слайдов, отображаются первые 4 кнопки пагинации.

_Переход к следующему слайду:_

- При переходе на слайд 2 или 3, кнопки пагинации остаются неизменными, показывая кнопки слайдов 1, 2, 3, и 4.
- При переходе на слайд 4, кнопки пагинации смещаются: показываются кнопки слайдов 2, 3, 4, и 5.
- Для каждого последующего слайда до предпоследнего, кнопки пагинации продолжают смещаться, показывая текущий слайд, два предыдущих и один следующий слайд.

_Переход к предыдущему слайду:_

- Если пользователь находится на последнем слайде и переходит назад, отображаются кнопки для предпоследних слайдов, так же смещаясь на одну позицию влево.
- При возвращении к первому слайду, отображаются первые 4 кнопки пагинации.

_Поведение на последнем слайде:_

- Когда пользователь достигает последнего слайда, показываются последние 4 кнопки пагинации.

```
*Пример:*

Допустим, у нас есть 10 слайдов. Поведение будет следующим:

Слайд 1-3: Кнопки пагинации показывают слайды 1, 2, 3, 4.
Слайд 4: Кнопки пагинации показывают слайды 2, 3, 4, 5.
Слайд 5: Кнопки пагинации показывают слайды 3, 4, 5, 6.
Слайд 6: Кнопки пагинации показывают слайды 4, 5, 6, 7.
-...
Слайд 9: Кнопки пагинации показывают слайды 7, 8, 9, 10.
Слайд 10: Кнопки пагинации показывают слайды 7, 8, 9, 10.

Такое поведение обеспечивает пользователю удобный доступ к просмотру слайдов, позволяя всегда видеть текущий, предыдущие и следующие слайды, если они есть.
```

### Вопросы и ответы

- Интерактивной частью блока является весь вопрос, например «Кто организатор? Какие сроки у программы?», а не только иконка с +.
